# AI/ML Research Paper Semantic Search Using Pinecone

Mini-project for University of Georgia CSCI 4370 Database Management Honors Option. It demonstrates how a vector database can store and retrieve AI/ML research papers by semantic meaning rather than exact keyword overlap.

## Motivation

Research questions are often conceptual: "memory-efficient LLM inference" might match papers about quantization, adapters, pruning, or low-rank adaptation. A vector DBMS stores embeddings so semantically similar papers can be found even when vocabulary differs.

## Main Features

- Download AI/ML paper metadata from the official arXiv API.
- Normalize, validate, deduplicate, and cache records as JSONL.
- Create or connect to a Pinecone serverless index with integrated embedding.
- Upsert title-plus-abstract text records without hard-coding vector dimensions.
- Search by natural-language research question.
- Filter by primary arXiv category and publication-year range.
- Find papers similar to a selected paper.
- Show database status in Streamlit.
- Evaluate latency, category proxy metrics, filter behavior, and optional precision@k labels.
- Run offline unit tests without consuming Pinecone API usage.

## Architecture

`scripts/fetch_papers.py` collects arXiv Atom feed data and writes `data/arxiv_papers.jsonl`. `scripts/ingest_papers.py` sends normalized records to Pinecone. `app.py` provides the Streamlit interface. `scripts/evaluate_search.py` runs repeatable evaluation queries.

See [docs/architecture.md](/Users/giangnguyendohoang/Documents/uga/csci4370/pinecone-aiml-paper-search/docs/architecture.md) for the Mermaid diagram.

## Pinecone Vector-data Model

- **Index**: One Pinecone index, default `aiml-paper-search`.
- **Namespace**: Logical partition, default `arxiv-papers`.
- **Record ID**: Stable ID derived from arXiv ID, such as `arxiv:1706.03762`.
- **Embedded text**: Combined title and abstract in `paper_text`.
- **Vector**: Generated by Pinecone integrated embedding from `paper_text`.
- **Metadata**: Title, abstract, authors, published date/year, primary category, all categories, paper URL, and source.

The current Pinecone Python SDK creates integrated-embedding indexes with `pc.indexes.create_for_model(...)`, upserts text with `index.upsert_records(...)`, and searches natural-language text with `index.search(..., inputs={"text": query})`. This avoids local embedding code and keeps the project to one required service key.

## Setup

Python 3.11 or newer is recommended.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env` locally or export variables in your shell. Do not commit `.env`.

```bash
export PINECONE_API_KEY="your-key"
export PINECONE_INDEX_NAME="aiml-paper-search"
export PINECONE_NAMESPACE="arxiv-papers"
```

You can check whether the local cache and Pinecone namespace contain data with:

```bash
python scripts/check_status.py
```

## Pinecone Account and API Key

1. Create or open a Pinecone account.
2. Create an API key.
3. Put the key in `PINECONE_API_KEY`.
4. Leave the default integrated embedding model unless Pinecone changes model availability in your account or region.

## Environment Variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `PINECONE_API_KEY` | empty | Required for Pinecone operations |
| `PINECONE_INDEX_NAME` | `aiml-paper-search` | Pinecone index name |
| `PINECONE_NAMESPACE` | `arxiv-papers` | Namespace for the arXiv collection |
| `PINECONE_EMBEDDING_MODEL` | `llama-text-embed-v2` | Pinecone integrated embedding model |
| `PINECONE_CLOUD` | `aws` | Pinecone serverless cloud |
| `PINECONE_REGION` | `us-east-1` | Pinecone serverless region |
| `PINECONE_TEXT_FIELD` | `paper_text` | Record field embedded by Pinecone |
| `ARXIV_DATASET_SIZE` | `1000` | Number of papers to collect |
| `DATA_DIR` | `data` | Local data directory |

## Download Dataset

```bash
python scripts/fetch_papers.py --limit 1000
```

The script respects arXiv's recommended delay between repeated calls and preserves an existing cache if the API is temporarily unavailable.

For offline testing only, a tiny sample dataset is included at `data/sample_papers.jsonl`.

## Ingest Papers

```bash
python scripts/ingest_papers.py
```

This creates the Pinecone index if needed, waits for readiness, and upserts records into the configured namespace.

## Launch Streamlit

```bash
streamlit run app.py
```

Example query:

```text
Efficient techniques for running large language models on devices with limited memory
```

## Run Evaluation

```bash
python scripts/evaluate_search.py --top-k 10
```

Outputs:

- `evaluation/results.csv`
- `evaluation/summary.md`

The included `evaluation/queries.json` has proxy labels such as expected categories and concepts. It does not fabricate relevance judgments. Add human-reviewed relevant record IDs before reporting precision@k.

## Run Tests

```bash
pytest
```

Optional Pinecone integration smoke test:

```bash
RUN_PINECONE_INTEGRATION=1 pytest tests/test_pinecone_integration.py
```

The integration test uses a test namespace and does not delete the main project index.

## Troubleshooting

- Missing API key: set `PINECONE_API_KEY`.
- Empty results: ingest data first and wait briefly for Pinecone write freshness.
- arXiv unavailable: rerun later; an existing JSONL cache is preserved.
- Pinecone model unavailable: set `PINECONE_EMBEDDING_MODEL` to another currently supported integrated embedding model.
- Wrong namespace count: confirm `PINECONE_NAMESPACE` matches the namespace used during ingestion.

## Known Limitations

- Relevance evaluation is mostly proxy-based until human labels are added.
- arXiv metadata is limited to public paper fields.
- Similar-paper search depends on the embedding model and the ingested dataset coverage.
- The app intentionally does not generate LLM answers; it focuses on vector DBMS operations.
